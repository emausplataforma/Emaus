LEIA-ME v2 - LOGO DA IGREJA NOS LINKS + PROTECAO CONTRA LINK QUEBRADO
Data: 02/10/2026

=====================================================================
1. O QUE O USUARIO VAI VER
=====================================================================
- Todo link que a igreja copia ou envia (painel, tela de configuracoes, mensagem do
  bot para o visitante) aponta para uma pagina que mostra o LOGO e o NOME da propria
  igreja no cartao do WhatsApp. Nenhuma igreja herda a marca de outra.
- A pagina /s/<slug> e gerada no servidor: titulo, descricao, og:image e
  twitter:image apontam para /api/public/church/<slug>/logo.png.
- Igreja sem logo enviado: aparece um SVG com a inicial da igreja (aviso: WhatsApp e
  Facebook podem nao mostrar SVG como imagem do cartao).
- Slug inexistente ou igreja pausada/bloqueada: 404 com pagina "Link invalido".

=====================================================================
2. O QUE MUDOU NA v2 (correcao importante)
=====================================================================
O frontend (GitHub Pages) foi publicado antes do backend (Railway). Enquanto o Railway
nao receber o codigo novo, a rota /s/<slug> nao existe la - e o "Link publico" que a
igreja copia apontaria para uma pagina 404.

A v2 resolve isso sem depender de ninguem lembrar de nada:

a) Ao abrir o painel, o app faz UMA checagem:  GET <API>/s/verificacao-de-link
   - API com o codigo novo -> devolve a pagina "Link invalido" (rota existe)
   - API com o codigo antigo (19/09) -> devolve "Cannot GET" (rota nao existe)
   O resultado vira apiRoutes.mode = 'modern' | 'legacy' | 'unknown'.

b) publicShareUrl():
   - 'modern'  -> usa o link curto  https://<API>/s/<slug>  (com cartao e logo)
   - 'legacy'/'unknown' -> usa o link do Pages  https://<Pages>/publica.html?igreja=<slug>
     que SEMPRE funciona, so nao tem o cartao bonito. NINGUEM recebe link quebrado.

c) Botao "Excluir visitante": some enquanto a API for 'legacy' (para ninguem clicar em
   algo sem efeito). Se mesmo assim um DELETE devolver 404, o app marca a API como
   antiga e avisa: "O cadastro continua salvo. A exclusao ainda nao esta ativa porque a
   API em producao precisa ser republicada no Railway."

d) Na tela de Configuracoes, a frase sob o link acompanha o estado: "E este link que
   abre com o logo da igreja na previa do WhatsApp" (API nova) ou "O cartao com o logo
   aparece assim que a API for republicada no Railway" (API antiga).

Nada de configurar: quando o Railway rodar o codigo novo, o link curto e o cartao ligam
sozinhos na proxima vez que o painel for aberto.

6. "NAO ESTA EXCLUINDO OS VISITANTES" (relato de 02/10/2026)
=====================================================================
Causa medida: a rota DELETE /api/church/visitors/<id> nao existe no build do Railway
(19/09/2026 14:56). Producao responde 404. Nada no navegador resolve isso.

Onde clicar: Acolhimento -> "..." na linha do visitante -> rodape do modal ->
"Excluir visitante" (o botao nao fica na linha da tabela).

Quem pode: somente a conta de pastor da igreja (church_admin). Recepcao e administrador
da plataforma nao veem o botao (regra de todas as escritas da igreja).

Bloqueio por design: visitante com cuidado em aberto da 409 e a mensagem
"Este visitante tem N acompanhamento(s) de cuidado em aberto. Conclua ou cancele o
acompanhamento antes de excluir o cadastro." -> resolva o cuidado e exclui.

Testado no codigo novo com Postgres real: 200 e linha removida + auditoria + fila do bot
cancelada; 409 no caso de cuidado aberto; 200 depois de concluir o cuidado; 404 ao tentar
excluir visitante de outra igreja (isolamento funcionando).
